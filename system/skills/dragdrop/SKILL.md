# 收拖入 / 内嵌界面：先读契约，再照这三点自查

**先 `spec("拖放")`**（契约 §4.2 那张六道关的表 + 可抄的骨架）—— 那是唯一真相，
这份技能只是提醒你别漏。

三个最容易翻车的点（都真机踩过）：

1. **别指望页面读 `dataTransfer.files`** —— Chromium 不给页面真实路径。
   路径只从宿主来：`moss.on('drop', d => d.items)`。
2. **拖放的提示只有一个，而且要自己收**：内嵌时宿主会铺罩子接住这一拖，于是
   ① 你会收到一次**假的** `dragleave`；② 你**再也收不到 `drop`**。
   规矩：`moss.on('captured')` 之后别信 `dragleave`；`moss.on('dragend')` 和
   `moss.on('drop')` 里都要把提示收掉。只写 `dragleave`/`drop` 的页面，
   症状就是"**松手之后提示一直挂在那儿**"。
3. **后端别把页面要调的方法挡掉**（内嵌模式的方法白名单）：页面回一句
   "没有这个方法 X"，整条链当场死 —— 而且这种错**只在真进程里才现形**，
   拿桩测参数形状是测不出来的。所以验收要**真跑**（`run_moss`）。
