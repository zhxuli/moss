# 给自己造一只手（自制工具）

**什么时候该用**：你需要一个**宿主没给你的能力**，而且**这次任务里要反复用**它 ——
比如截屏、截某个窗口、量一张图的像素、解析某个格式、反复查一个本地接口。
（一次性的活别造工具，直接写脚本进你的包就行。）

**造出来的东西谁看得见**：**用户看不见**。它不在插件页、不是 `:别名`、不算包 ——
它住在你自己那一层，只在 AI 页一个折叠小块里露一眼。所以**别往 `user_data/pkgs/` 里塞**
（那是面向用户的目录，混进去用户会觉得乱，而且他能一键删掉）。

## 写到哪

```
user_data/ai/tools/<名字>/TOOL.md     ← 给模型看的说明书（frontmatter 四个字段）
user_data/ai/tools/<名字>/run.py      ← 那只手本体
```
* `<名字>` 只用小写字母 / 数字 / `-` / `_`，**不能和内置工具撞名**
  （内置的：list_dir、read_file、grep、edit_file、write_file、spec、run_moss、
  snap_clean、skill、answer、done）。
* `system/ai/tools/` 是**出厂件**（随版本走），你**只能读、不能写**。
* 一只工具一个目录；同目录里可以再放别的文件，`run.py` 能 `import` 它们。

## TOOL.md 长这样

```
---
name: shot
description: 截屏（整屏或某个窗口）存成 png，回绝对路径和尺寸
params:
  target: 窗口标题里的关键词（不填 = 整个屏幕）
  out: 存到哪个文件（不填 = 自动起名）
timeout: 60
---
（这一段是给人看的说明，模型看不到。）
```
* `description` **必须有** —— 没有它这工具进不了表。
* `params` 是**参数名 + 一句说明**（工具表里全是**字符串**，别指望模型给你传数字/数组）。
* `timeout` 不写就是 60 秒，最多 300。

## run.py 的契约

* 启动方式：`<自带运行时>python.exe system/bootstrap.py <你的目录>/run.py`
  —— 自带运行时是**隔离模式**，所以必须经 `bootstrap.py`；好处是**同目录的兄弟文件能 import**。
* **参数**：stdin 一行 JSON（就是模型给的那些），同时也在环境变量 `MOSS_TOOL_ARGS` 里。
* **回话**：`stdout` 的文本**原样**回给模型（截尾 60 行 / 4000 字）。
  ⇒ **别打印进度、别打印调试信息**，`stdout` 只留给"要跟模型说的话"；调试走 `stderr`。
* 退出码非 0 会在前面标一句（照样把 stdout 给它，方便它自己修）。
* `cwd` = 你的工具目录；`MOSS_HOME` / `MOSS_USER_DATA_DIR` 原样带下去。
* 卡住超过 `timeout` 会被杀掉，回一句「超时」。

最短能跑的样子：

```python
import json, sys
args = json.loads(sys.stdin.read() or "{}")
print("收到：%s" % json.dumps(args, ensure_ascii=False))
```

## 硬规矩（踩了会挨打）

1. **写完不算生效 —— 要向用户说清楚**：工具表是**这次任务开工那一刻定死**的，
   你这一步新造的手**这一次跑用不了**，要**用户点一次「允许」**、下一次跑才进表。
   所以：要么先把它写好、告诉用户"我造了一只 X，你在 AI 页点一下允许，我下次就能用"，
   要么先用别的手段把这次任务干完。
2. 用户**点允许之前**他可能先「看一眼」你写的 `TOOL.md` 和 `run.py` —— 写清楚、别藏东西。
3. 以后你要是**改了** `TOOL.md` 或 `run.py`，允许状态会**自动作废**（要重新允许）。
   所以改完要跟用户说一声。
4. 别拿它当"绕开写权限"的后门：这只手能碰的文件，跟你在这次任务里能碰的**一样多**
   （你自己的包 + 你自己的工具目录）。要动出厂件 / 宿主，那是**必须由人来做**的事。
5. 依赖：自带运行时里已经有的库可以直接用（`PIL` / `pyautogui` / `requests` / `numpy` …）。
   **装不了新库**，也别假设有网络。
