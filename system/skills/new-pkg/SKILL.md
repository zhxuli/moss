# 写一个新包：照这个顺序走（每一步都别跳）

1. `list_dir` 看一眼 `user_data/pkgs/`（有没有重名）。
   ★ **硬闸在 `run_moss("--new <id>")`**：它现在会同时检查 user / system 两层的
   **id 和别名**；撞了会返回退出码 1 和明确的"已被占用 / 别名冲突"。看到这句就换一个 id，
   别把失败当成功，也别自己拼目录绕过。
2. **读契约**（读一次就够，别反复读）：
   * `spec("pkg.json")` —— 字段表 + `params`（含 `rest`）+ `drop` 声明；
   * 要**界面**就再 `spec("界面")`（`ui.embed` + 垫片那套）；
   * 要**能收拖入**就必须 `spec("拖放")` —— 那张六道关的表，漏一道的症状
     就是"拖进来没反应 / 提示不消失"。
3. 骨架优先：`run_moss("--new <id>")` 能生成一个能跑的包（`pkg.json` + `run.py` + `AGENT.md`
   + `icon.svg`），比从零写稳。要界面 / 拿不准就照出厂插件 `system/pkgs/skill/` 抄
   （`pkg.json` + `main.py`/`embed.py` 两种跑法 + `ui/` 一整套，完整真插件）。
3.5 **图标别忘**（`icon.svg`，界面列表 / 详情页那颗）：骨架里那颗是中性的，换成跟这个包
  干什么相配的图形（48×48 viewBox，别写死宽高、别引外链资源）。没有它，列表只能画名字
   首字兜底 —— 看着就是"图标忘了做"。
4. 改完 → `run_moss(":<id> <示例参数>")` → **退出码 0** → 再 `done`。
5. `done` 里写：包 id、文件清单、验收用的那条命令 + 它的结果、以及没验到的部分。

**别忘的几条**（都是踩过的）：
* `id` 只能小写字母开头、`[a-z0-9_-]`、≤32 字符；
* `drop` 声明必须和代码事实一致（`ext` 收哪些格式 = 代码真能处理哪些）；
* 数据写 `MOSS_PLUGIN_DATA_DIR`，别写包目录；
* 参数从 `MOSS_PKG_PARAMS`（JSON）读，别人肉切 `sys.argv`；
* 实测：`moss :<id>` 和带参数两种用法都要能跑（这是"一个包两种用法"的约定）。
* 第三方库：不要因为宿主没预装就放弃。缺少的库用 pkglib 技能装到当前包自己的 packages/，入口最前面 import deps；pkglib 没授权就先让用户允许。
* 默认 id：my-first 只是临时名，需求明确后要主动用 ask 问用户是否改名，给 2 到 4 个候选 id 和中文名；用户同意后用 run_moss 执行 --rename 旧id 新id。绝不能直接改文件夹名或 pkg.json 的 id。
