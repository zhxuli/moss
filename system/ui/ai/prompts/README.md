# 提示词怎么改（AI 工作台）

这个目录里的 `*.md` 是 **AI 工作台**的提示词，**不是代码** —— 改它们不用碰 py，
改完**重启 moss** 就生效（`system/ui/**` 不在 exe 里）。

## 两层：user 盖 system（和包那套一个规矩）

```
system/ui/ai/prompts/<名字>.md     ← 出厂默认（跟着 moss 发，升级会更新）
user_data/ai/prompts/<名字>.md     ← 你自己的覆盖版；**同名就整个替换前面那份**
```

* 只想改一小段：把 system 那份**整个复制**到 `user_data/ai/prompts/` 再改
  （是"整份替换"，不叠加）。
* 删掉 `user_data` 里那份 = 退回出厂版。
* 两层都找不到某个名字时，**不会偷偷用内置兜底** —— 界面上会直接告诉你缺哪个文件
  （免得你以为"AI 今天变笨了"）。

## 现在有哪些

| 文件 | 什么时候装 |
|---|---|
| `system.md` | **每次都装**：人格 + 五条硬规矩 + 干活路子 |
| `edit.md` | **每次都装**：改文件的格式（search/replace）与"收工前必须跑" |

★ **"方法论"不在这里**（`V-278`）：写新包 / 收拖入 那两套指导搬去了 **`system/skills/<名字>/SKILL.md`**，
**按需读** —— 系统提示里只列"名字 + 描述 + 路径"，模型需要时自己用 `skill(名字)` 把正文读出来
（这就是 Pi 的 skills 那套做法）。两层规矩一样：`system/skills/` 出厂、`user_data/skills/` 你的覆盖版
（**同名目录整个替换**）。
**为什么改**：以前是按任务关键词"整段注入"（出现"写/新/建"就把 `new_pkg.md` 全文塞进系统提示）——
靠猜、不好扩展（加一门只能改 Python 里那张关键词表）、而且带不了样板/骨架。

## 两条别违反的

1. **别把契约正文抄进提示词**。契约（`system/spec/插件契约.md`）是唯一真相，
   提示词里只说"什么时候去读哪一节"；要真正拿到内容，用 `spec` 工具**当场从契约里切**
   —— 这样契约改了，AI 立刻跟着变，不会出现两份互相矛盾的说法。
2. 提示词是**给模型看的**：写得短、写成命令式的规矩；解释留给 `AGENTS.md` 和账本。
