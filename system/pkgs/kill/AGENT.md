# kill —— 按名字/端口杀进程

```bash
moss :kill node        # 进程名里包含 node 的都列出来（不分大小写）
moss :kill 8080        # 找正在监听 8080 的进程
moss :kill             # 不给参数 → 只打用法，什么也不做
```

## 它到底会做什么

1. **先找、再问、最后才杀**：命中之后列出菜单（按**可执行文件路径**分组合并，
   每组显示 名字 / 几个进程 / CPU / 内存 / 占用端口），用上下键选一组回车；
   也可以选「清理以上全部进程」或「取消并退出」。**你不选，它一个进程都不动。**
2. **杀的方式**：`psutil` 的 `terminate()`，然后最多等 3 秒。等不到就算失败，
   **不会**自动升级成强杀（不做 `kill -9`）。
3. **要管理员权限才准**：非管理员读不到全部网络连接和路径 ——
   按端口杀尤其需要管理员，否则可能"明明占着端口却找不到"。

## 参数

| 参数 | 含义 |
|---|---|
| `query` | 纯数字 = 端口号（找**监听**该端口的进程）；其它 = 进程名，**包含**匹配、不分大小写 |

多余的参数会被宿主丢掉（老版 `pa :kill` 也只认第一个）。

## 给 AI / 自动化用的话

`pkg.json` 里 **`ai.expose` 是 `false`**：这条命令会真杀进程，而且杀哪个要人在菜单里选，
不适合让 AI 直接调用。真要做自动化，应该另写一个"给定 PID 才杀"的包，
并且带上确认与白名单，而不是复用这个交互式菜单。

## 来历
