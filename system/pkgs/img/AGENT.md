# img —— 给 AI / 脚本看的调用契约

> 这是 moss 包标准里的 **`AGENT.md`**（在 `pkg.json` 的 `docs.agent` 里声明）：
> `README.md` 给人看、**`AGENT.md` 给 AI 看**（用法 / 副作用 / 失败模式，可长文）。
>
> 语法只有一份真相在 `cli.py` 的 `USAGE` 里，这份是把它摊开讲清楚；
> **两者不一致时以 `cli.py` 的 USAGE 为准**（`moss :img -h` 打印的就是它）。

## 是什么

一个图片批量压缩 / 转换工具。支持 `jpg` `png` `webp` `ico`，
输入支持 `jpg jpeg png webp bmp gif tiff`。

**同一个包两种用法**：

| 调用 | 行为 |
|---|---|
| `moss :img`（**不带任何参数**） | 打开图形界面（在 moss 里是**内嵌**，也能自己开一扇窗） |
| `moss :img <参数...>` | 命令行模式 |

## 界面：一份页面两种跑法（`V-48` / `V-225`）

| 怎么起 | 走哪条路 | 代码在哪 |
|---|---|---|
| 在 moss 的「界面」选项卡里**内嵌** | 宿主给 `MOSS_UI_EMBED=1`，把它起成**后端进程**：不开窗口，在 stdin/stdout 上说 JSON 行 | `embed.py`（协议）+ `ui/moss-embed.js`（页面侧垫片） |
| 独立窗口 | pywebview 开一扇窗 | `gui_web.py` |
| 本机没 pywebview / WebView2 | tkinter 基础界面 | `gui_tk.py` |

**★ 两条路共用同一份 `gui_web.Api`** —— 所以 `Api` 的每个方法都只收**一个 dict**
（`params`），字段按名字取。垫片两种环境都只传一个参数（内嵌是把
`{"id", "method", "params"}` 送进后端进程的 stdin），**别改回位置参数**，一内嵌就散架。
页面那侧的桥只有 `ui/src/bridge.js` 一处（`ROUTES` 表把页面的位置参数翻成字段名）。

**内嵌协议**（一行一个 JSON）：
```
宿主 → 我们： {"id": 1, "method": "scan", "params": {"dir": "D:\\pics"}}
我们 → 宿主： {"id": 1, "ok": true, "result": {…}}
```
★ 规矩：**stdout 只许出 JSON 行**。日志走 `_log()`（stderr）—— 宿主对"不是 `{` 开头"的行
会当输出收进命令行（无害），但**把一条 JSON 拆成两行就真把协议撕了**（别用多行 print）。
`attach` / `_scan` / `_remember` / `_on_closing` / `save_config` / `set_title`
这几个在 `Embedded.HIDDEN` 里，页面调不到（内部用 / 只在独立窗口那条路上有意义）。
**`push_drop` 不在里面**（`V-227`）：那是页面**自己**把宿主给的真路径塞回来的那条路，
挡掉它 = 拖进来什么都不发生（真机上就是一句"没有这个方法 push_drop"）。

**内嵌时拖放改走宿主**：真路径只有宿主拿得到（Chromium 不给页面 `File.path`）。
宿主把**真路径**作为 `drop` 事件送进页面 → 页面 `push_drop` 塞回后端 → 原来
`take_drop()` 那条管线（`core.expand_dropped` 判文件夹/清单、按配置过滤、记历史）
**一个字都没改**。内嵌时也不去写窗口标题（窗口是 moss 的）。

★ **拖放提示的生命周期**（`V-226`，真机上踩到过"松手之后提示不消失"）：宿主铺的透明罩子
把这一拖接过去之后，页面会收到一次**假的** `dragleave`，而且**再也收不到 `drop`** ——
所以"松手收提示"这件事只能听宿主的：`moss.on('captured')` 之后不信 `dragleave`，
`moss.on('dragend')` / `moss.on('drop')` 里都收掉（独立窗口那条路另挂 `window` 的
`dragend` / `blur` 兜底）。规矩原文在 `system/spec/插件契约.md` §8 第 8 条。

**怎么验**（改完先跑这三条）：
```bash
.\system\runtimes\python\3.12\python.exe tools\img内嵌探针.py   # 内嵌后端：协议+业务 24 条
python tools\包界面检查.py img                                   # 这一页还画得出来吗
python tools\界面预览.py img-ui                                  # 宿主→iframe→后端 整条链
```
（探针自己会去起无头 `msedge`，本机两边都用 3.12 跑过；系统 python 3.13 那份也跑通了 ——
后端真正的运行时是 moss 自己挑的那个，跟用哪个 python 起探针无关。）

## 调用方式

```
moss :img [格式] [质量] [宽度] [文件/通配符...] [选项]
```

**参数顺序随便。除了下面标注"必须"的，全都可以不写。**

| 参数 | 写法 | 说明 |
|---|---|---|
| 格式 | `jpg` `png` `webp` `ico` | **可不写**。不写 = 保持原格式（每张图各存各的） |
| 质量 | `60%` 或 `60` | 1–100。裸数字 **≤100** 按质量算。默认 80 |
| 宽度 | `1200` 或 `1200px` | 裸数字 **>100** 按宽度算。只缩不放。`ico` 忽略它 |
| 文件 | `a.png` `*.png` `logo*.jpg` `D:\图\*.jpg` `**/*.png` | 可写多个，也可不写 |
| 目录 | `D:\图` | 源目录。写了之后通配符**相对它**解析 |
| 扩展名过滤 | `jpg;png` | 老写法，等价于只处理这两类 |
| `/` | 单独一个斜杠 | 写回源目录（**覆盖原图**） |
| `-o <目录>` | | 输出到指定目录（原图不动） |
| `-s 16,32,256` | | 只对 `ico` 有意义：生成的 ico 里装哪几档尺寸 |
| `-h` | | 打印用法 |

### 文件不写时会处理什么

当前目录（或你给的源目录）下**所有支持的图片**，不看它们原来是什么格式。

## ⚠️ 必须注意：输出位置

**`/` 和 `-o` 至少要写一个。**

| 情况 | 行为 |
|---|---|
| 写了 `/` 或 `-o <目录>` | 直接用，**不会再问任何确认** |
| 两个都没写 + **有终端** | 弹出上下选择菜单，**必须按 ↑↓ 选中再回车**；直接回车 = 取消 |
| 两个都没写 + **没有终端**（管道 / 被程序调用） | **直接报错退出（退出码 2）**，不会卡住等输入 |

所以 **AI / 脚本调用时必须带上 `/` 或 `-o <目录>`**，否则命令会失败。

推荐 AI 一律用 `-o <目录>`：它是**非破坏性**的（原图不动），
`/` 会覆盖或删除原图，不可撤销。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部成功 |
| 1 | 有文件处理失败 / 没找到图片 / 参数错误 |
| 2 | 没有终端却也没指定输出位置 |
| 130 | 用户在菜单里取消 |

## 输出

全部是文本，打到 stdout（`[已保存] 至: <路径>` 一行一个文件）。
结尾有 `所有任务已成功完成。`（成功）或 `[错误] ...`（失败）。
**没有结构化输出**（`output.mode` 目前是 `text`）。

## 例子

```
moss :img ico a.png -o D:\out          只把 a.png 转成 ico，放到 D:\out
moss :img ico a.png b.png -o D:\out    只转这两个
moss :img ico *.png -o D:\out          只转当前目录的 png
moss :img webp -o D:\out               全部转 webp 80%
moss :img 1200 -o D:\out               全部缩到 1200 宽，格式不动
moss :img 60% -o D:\out                全部按 60% 重压，格式不动
moss :img webp 60 1200 -o D:\out       质量 60、宽 1200
moss :img ico -s 16,32 *.png -o D:\out 只要 16 和 32 两档的 ico
moss :img webp D:\图 *.png -o D:\out    换源目录 + 通配符
moss :img jpg 90% /                    原地覆盖转 jpg（原图会被替换）
```

## 不要做的事

- **不要不带 `/` 或 `-o` 调用**：非交互环境下会直接失败。
- **不要用 `/`**，除非你确实要覆盖原图；AI 默认应该用 `-o`。
- 别加 `-y`：为了兼容还接受，但已经没有意义（指定输出位置就是确认）。
- 别指望它递归：默认只看当前目录一层，要递归得用 `**/*.png` 这种写法。
