# github · 给 AI 看的说明

> 本文件是**给 AI / Agent 读的**（人看界面本身）。写清楚"怎么调、有什么副作用、会怎么失败"。
> ★ 这个包是**界面型**的：它的门面是 `ui/`，但 `main.py` 的**命令行那条路同样是一等公民**
> （每条动作都会先打印"等价命令"，这是这个包存在的意义）。

## 干什么
GitHub / Git 的可视化助手：**每个按钮都告诉你它替你敲了哪一条 git / gh 命令**。
管仓库状态、远端同步、磁盘（含"残存盘符"）、分支 / 提交 / PR / issue，记住用过的路径。

## 三种跑法
| 怎么起 | 走哪条路 | 代码 |
|---|---|---|
| `moss :github` | 独立窗口（pywebview 开一扇窗） | `run_window()` |
| 在 moss 的「界面」选项卡里点运行 | 宿主给 `MOSS_UI_EMBED=1` ⇒ **不开窗**，在 stdin/stdout 上说话 | `Embedded` 类 + `ui/moss-embed.js` |
| `moss :github action=status path=D:\code\x`（或直接跑 `main.py`） | 命令行：**先打等价命令**，再打命令输出 | `cli()` |

★ 上面写的是**默认配置**下的调法；本机实际怎么调见下一节。

## ★ 长任务：别让一条命令把界面拖死（2026-10-25 加）

推 / 拉 / 保存这类会联网、可能跑几分钟的操作，**不要**直接 `call('sync')` 然后干等：

| 方法 | 干什么 | 返回 |
|---|---|---|
| `job_start {method, label, params}` | 把 `method`（任何 Core 方法，如 `sync` / `commit_all` / `shield`）扔到后台线程跑 | **立刻**返回 `{ok, id}` —— 这条 RPC 秒回，永远不会超时 |
| `job_state {id, n}` | 看进度 | `{state: running/done/cancelled, elapsed, silent, lines[], result}` |
| `job_cancel {id}` | 停下（真的 `taskkill /T` 那个子进程树） | `{state}` |

为什么非得这么干（真机踩出来的三条）：
1. `ui/moss-embed.js` 里每条 RPC 原来写死 **30 秒**上限 —— 首次推送大仓库时三十秒一到就报
   "后端没回话"，可 git 还在传，人以为失败又点一次。（现在提到 90 秒，而且长操作走的是
   `job_*`，根本用不到这个上限。）
2. 内嵌模式下 **stdout 是协议通道**（一行一个 JSON）。`main.py` 里到处是 `print(...)`，
   这些行进去只会被宿主当垃圾丢掉 ⇒ 界面上什么也看不到。现在 `Embedded` 一启动就把
   `sys.stdout` 换成 `_StdoutToProgress`，**所有 print 自动改道成进度**（进 `job_state` 的
   `lines`）。`_live()` 里**绝不能再 print**：那会自己叫自己（探针里表现为同一行刷 80 遍）。
3. 网络卡住时 `p.kill()` 杀不动读管道的线程 ⇒ 主循环自己查 `_job_cancelled()`，一看到就收尾。

`sync.log`（`DATA_DIR/sync.log`）只记**慢的（≥3 秒）和失败的**命令：耗时、退出码、命令原文、
最后 10 行输出。`action=gitlog` 或界面上「更多功能 → 同步日志」读它。必然失败的探路命令
（`rev-parse @{u}` 之类）不记，免得把有用的挤掉。

| 写法 | 本机实测 |
|---|---|
| `moss user_data/pkgs/github/main.py action=version` | ✔ 退出码 0（宿主报"唯一可用候选"，**推荐**） |
| `moss github action=version` | ⚠ 能出结果，但走的是"历史重跑"退路（提示 `[历史] 文件系统里没有 'github'`），**不可靠、别依赖** |

## 怎么调（命令行）
```
moss :github action=status path=D:\code\my-repo
moss :github action=commit arg="修了个 bug" path=D:\code\my-repo
moss :github action=disks
```
| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `action` | string | 否 | 要跑的动作；**留空 = 开界面**。可选值见下表 |
| `path` | string | 否 | 仓库目录；留空 = 拖进来的目录 / 上次用过的 / 当前目录 |
| `arg` | string | 否 | 动作的附加参数（提交信息 / 分支名 / clone 地址） |

动作（`action`）一览 —— **每一项的"等价命令"就是它真正跑的**：

| action | 等价命令 | 改什么 |
|---|---|---|
| `status` | `git status --short --branch` | 只看 |
| `log` | `git log --oneline --graph --decorate -n 20` | 只看 |
| `diff` | `git diff --stat` | 只看 |
| `branches` | `git branch -vv` | 只看 |
| `remotes` | `git remote -v` | 只看 |
| `tags` | `git tag --sort=-creatordate` | 只看 |
| `fetch` | `git fetch --all --prune` | 只更新远端账本（联网） |
| `pull` | `git pull --ff-only` | 动代码（联网；只快进） |
| `push` | `git push --progress`（没跟踪分支时 `-u origin <分支>`） | 动远端（联网） |
| `loc` | （本机统计：按扩展名数行数） | 只看：多少行代码。两份口径（git 跟踪的 / 磁盘上全部） |
| `precheck` | （本机统计 `git ls-tree -r -l HEAD`） | **只看**：这一推多大、有没有 GitHub 装不下的文件 |
| `bigfiles` | （本机统计 `git ls-files` + 文件大小） | 只看：版本库里谁占体积 |
| `gitlog` | （读 `state/github/sync.log`） | 只看：慢命令的耗时 / 退出码 / 输出尾巴 |
| `ignore` | （读 `.gitignore`，`arg=规则` 则加一条） | 改 `.gitignore` |
| `shield` | 写 `.gitignore` + `git rm -r --cached -- <路径>` | 从版本库去掉（磁盘文件不动） |
| `untrack` | `git rm -r --cached -- <路径>` | 只从版本库去掉，**不动 `.gitignore`** |
| `amend` | `git commit --amend --no-edit` | 并进上一条提交（只在没推过时用） |
| `add_all` | `git add -A` | 动暂存区 |
| `commit`（`arg=` 提交信息） | `git commit -m "<信息>"` | 本地历史 |
| `new_branch`（`arg=` 分支名） | `git checkout -b <名>` | 切分支 |
| `switch`（`arg=` 分支名） | `git checkout <名>` | 切分支 |
| `stash` | `git stash push -u` | 收起改动 |
| `stash_pop` | `git stash pop` | 取出改动 |
| `init` | `git init` | 普通目录一键变仓库（不带 `-b`，老 git 也认） |
| `clone`（`arg=` 地址） | `git clone <地址>` | 下载仓库 |
| `disks` | 本机 API（`GetLogicalDrives` + `disk_usage`） | 只看 |
| `version` | `git --version` | 只看 |
| `gh_auth` / `gh_pr` / `gh_issue` / `gh_repo` | `gh auth status` / `gh pr list` / … | 只看（要装 `gh`） |

## 返回（结构化）
`MOSS_RESULT_FILE` 里是 JSON：`{"ok": bool, "action": str, "path": str, "cmd": str, "out": str, "code": int}`。
退出码：`0` = 成功；`1` = 命令跑了但失败；`2` = action 不认识；`3` = 目录不存在。

## 界面那边（内嵌协议）
一行一个 JSON（`{` 开头的才算消息），**stdout 上别出多行 `print`**，日志一行一条：
```
{"id": 1, "method": "snapshot", "params": {"path": "D:\\code\\x"}}
{"id": 1, "ok": true, "result": {...}}
```
页面能调的方法（`Core` 的公开方法，**一个都不许进任何 HIDDEN 名单**）：
`boot` `actions` `snapshot` `browse` `disks` `net_probe` `gh` `set_path` `forget_path` `run_action` `file_op`
`timeline` `show_commit` `switch_branch` `sync` `commit_all` `restore` `mirror` `remote_repo`。

后 8 个是 2026-10-08 这轮按用户要求加的：

| 方法 | 干什么 | 等价的命令（界面会把每一步都摆出来） |
| --- | --- | --- |
| `timeline` | 时间线 + 本地/远端分支 + 标签，并标出每条提交"已推送 / 只在本地" | `git log --pretty=…` + `git for-each-ref`（**不联网**） |
| `show_commit` | 一条提交的详情：作者 / 文件清单（± 行数）/ 补丁 | `git show <ref>` |
| `switch_branch` | 切分支（`create=true` 新建）；工作区脏时会拦住并给出路 | `git checkout [-b] <名>`，脏且有 `stash=true` 时先 `git stash push -u` |
| `sync` | 一键同步：fetch →（落后且干净就）pull --ff-only →（领先就）push | `git fetch --all --prune` / `git pull --ff-only` / `git push` |
| `commit_all` | 全部改动一次提交（`push=true` 顺手推） | `git add -A` + `git commit -m` +（可选）`git push` |
| `restore` | 恢复某条提交。`mode=branch`（默认）= 检出成 `restore-…` 新分支；`mode=worktree` = 工作区拉回去 | `git checkout -b restore-…` / 先 `git stash push -u` 备份再 `git reset --hard` |
| `mirror` | 镜像：`gh_create`（GitHub 建仓库并推）/ `local_clone`（`clone --mirror` 本地备份）/ `add_remote`（加镜像远端 + 推分支标签） | `gh repo create …` / `git clone --mirror` / `git remote add` + `push --all` + `push --tags` |
| `remote_repo` | GitHub 上这个仓库长什么样（描述 / ★ / 默认分支 / 最后推送） | `gh repo view --json …` |
| `pull_overwrite` | **「从 GitHub 覆盖下载」**：fetch →（有改动先 stash 备份）→ reset --hard 上游。本地变得和 GitHub 一模一样 | `git fetch --all --prune` +（脏时）`git stash push -u` + `git reset --hard <upstream>` |

这 8 个都回一份 `{ok, steps:[{label, cmd, ok, ms, out, why}], path, why, ms, cmd, at}`：
**每一步带着自己的等价命令和输出** —— 界面「命令与结果」页就是照着它画的，所以界面上不会再有"点了不知道干啥"。

## 拖放
`pkg.json` 里 `drop.dir.cwd = true` ⇒ **拖一个文件夹进来 = 把它设成当前仓库**（靠工作目录传进来，
参数里没有任何东西）。拖到内嵌那一帧上时用宿主发的 `drop` 事件（`d.items` 是真实路径）。
页面上只有一个"松手"提示，生命周期按契约 §8 第 8 条管：`captured` 之后不信 `dragleave`，
收提示只能靠 `dragend` / `drop`。

## 副作用
- 写文件：只有**路径记忆** `MOSS_PLUGIN_DATA_DIR/paths.json`（不写自己的包目录）。
- 联网：`fetch` / `pull` / `push` / `clone` / `net_probe` / `gh *`（其余动作全是本机操作）。
- 跑外部命令：一律 `git`（`gh` 只在"gh"那组动作里）；60~300 秒超时，`GIT_TERMINAL_PROMPT=0`
  （不会卡在等密码上）。

## 失败模式
- 目录不是 git 仓库 → `{ok:false, why:"… 不是一个 git 仓库"}`，退出码 1，**不动任何东西**。
- `commit` / `switch` 之类没给 `arg` → `{ok:false, why:"这个动作要填：…", needArg:"…"}`。
- `gh` 没装 / 没登录 → 界面右上角与 gh 那组按钮会说明；跑 `gh_*` 会回 `gh` 自己的报错。
- 网络不通 → 明确的 `why`（有的是超时文案）；`net_probe` 会报往返耗时。

## 还没验的
- 真机上的**拖放**（需要人手拖一次）：代码按契约 §8 那条骨架写全了六道关，
  但"拖进来"这一步没有自动化过。
- `gh` 那组动作 + `mirror mode=gh_create` + `remote_repo`：这台机器上**没装 gh**，
  所以只验了"缺 gh 时怎么优雅地说明"，没验真调用。
- 内嵌（`MOSS_UI_EMBED=1`）那条路是用探针（stdio 协议 + 建真仓库跑）验的，
  **没在 moss 的「界面」选项卡里用鼠标点过** —— 视觉观感（配色 / 排版）只有人眼能判。
- 界面的 24 条静态检查（`el()` 的 id 对得上、没引外网资源、`node --check` 过）是探针查的，
  不等于"运行时没 JS 报错"。

## 怎么自己验（不用装东西）
探针在 `MOSS_AI_TMP` 那份里（`probe_backend.py`）：它会现造一个真 git 仓库 + 一个裸仓库当远端，
把上面每个方法都跑一遍并按命令断言（`git add -A` / `git stash push` / `git reset --hard` /
`clone --mirror` …），再起一个 `MOSS_UI_EMBED=1` 的后端走一遍 stdio 协议，最后做界面静态检查。
**全过才退出码 0**。改完代码跑它，比人肉点界面快得多。
