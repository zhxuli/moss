# path —— 查看/管理 Windows 用户 PATH（带备份/恢复）

```bash
moss :path                      # 不带参数 = 打开界面
moss :path add D:\tools\bin     # 加进【当前用户】的 PATH
moss :path add                  # 省略路径 = 这个包自己的目录
moss :path remove D:\old\bin    # 从【当前用户】的 PATH 移除
moss :path help                 # 打用法
moss :path D:\tools\bin         # 拖一个文件夹进来（或这么敲）= add 那条目录
```

## 这包干什么

**界面**：一份网页（`ui/index.html`，Vue 3），两种跑法（`V-48` / `V-200`）——
内嵌进 moss 的「界面」选项卡（`pkg.json` 的 `ui.embed`），或者 `moss :path` 自己开窗口。
`V-213` 起按另一版设计稿重做：zinc 中性色、卡片、备份时间线、底部 Toast，深浅跟随系统。
**★ 不带任何 CDN**（设计稿引的 Tailwind / lucide / SortableJS / Google Fonts 一个都没用）：
工具类按同一套数值手写成 `ui/style.css`，图标本地化在 `ui/icons.js`，拖动排序用浏览器自带的
HTML5 拖放 —— 这个包**离线可用**（探针里钉着"一个外网资源都没加载"）。

- **按注册表里的原顺序**列出当前用户 PATH（上下位次就是 PATH 的优先级 —— 顺序决定同名命令
  谁赢，所以界面不排序）；**目录已经不存在的**那几条标红带斜纹（带 `%VAR%` 的不判，免得误伤）
- **按住行左边的把手拖动 = 调优先级**（`V-213` 新加的：拖动只改草稿，点「保存修改」才写回）
- 每行悬停出三颗小按钮（**图标 + 文字**，和别处一致）：**复制** / **拿出来改**（填回上面的
  输入框、从列表里拿掉，改完点「添加」放回去）/ **删除**
- 顶上一颗「**添加**」，干两件事：输入框**留空**点它 = 弹文件夹选择框；输入框**填了路径**
  点它 = 先问后端"这是不是个目录"（是文件就加它所在的目录，不存在就报错、输入框一个字不动）。
  输入框里一边打字一边给提示（不像路径 / 盘上没有）
- **先改后存**（`V-211`）：加 / 删 / 去重 / 清失效 / 拖动**都只改界面上的草稿** —— 新加进来的
  那几条一直高亮着「未保存」（绿色 + 左边一道竖线），右上角「保存修改」（**明亮的蓝**）跟着
  亮起来；点它才**一次**写回注册表、广播一次；「撤销」放弃草稿回到注册表里现在的样子。
  有草稿时点「刷新」（右上角那颗图标）会先问一声
- **操作按钮有事才出现**（`V-213`）：有重复才给「去重」、有失效才给「清理失效」、改了才给
  「撤销 / 保存修改」—— 没事的时候那一排整个不占地方。反馈一律走底部 **Toast**，
  底栏只留"总计 N 条路径"和后端自证（Python 版本 + 数据目录）
- **拖文件夹进窗口 = 加它**（拖**文件**则取它所在的目录，同样只进草稿）；拖动中会铺一层提示
  （拖进 moss 的「界面」选项卡那一帧里也算 —— 见契约里 `drop` 事件那一行）
- 布局**永远是左右两栏**（`V-215`：不做"窄了塌成一列"的自适应）：左边把剩下的都吃掉 = PATH
  列表，右边**固定 360px** = 备份时间线
- **行的把手和工具按钮、备份卡片上那三颗，全是浮在上面的**（半透明 + 毛玻璃）：不 hover 的
  时候它们**一点宽度都不占**，路径/名字能用满整行，鼠标放上去才滑出来（`V-215`）
- **备份**把当前 PATH 存成一行一个路径的文本，存之前可以给它起个名字（留空 = 时间戳）；
  时间线上的卡片**鼠标一放上去就自动展开对比**（`V-214`）、移开自动收；点「对比」= 把它
  **固定住**（移开也不收，按钮变成「已固定」，再点一下取消）。对比是 **+ 增加 / - 减少 /
  = 相同** 三色（默认只列差异，「显示全部」才把一样的也列出来），而且**比的是你界面上的那份
  清单**（存没存都算 —— 草稿改了它跟着变，是本地算的、不经过后端）；**双击名字改名**（只换
  文件名，内容一个字不动），点「恢复」才写注册表；卡片上还能删某一份

**命令行**：`add` / `remove` / `help`（别名见 `pkg.json` 的 `params.desc`）。
省略 `[路径]` 时操作的是**这个包自己的目录**。

## 参数

只有一个 `rest: true` 的参数 `args`：宿主把包名后面那一整串**原样**交给包，
由包自己解析（宿主不拆词、不做引号转义）。带空格的路径请自己加引号：

| 参数 | 含义 |
|---|---|
| 留空 | 打开界面 |
| `add [路径]` | 加进 PATH；省略 = 这个包自己的目录。别名 `register` / `reg` |
| `remove [路径]` | 从 PATH 移除；省略 = 这个包自己的目录。别名 `unregister` / `del` |
| `help` | 打用法。别名 `?` / `-h` / `--help` |
| 一个**存在的目录** | 当成 `add 那个目录`（拖文件夹进来走的就是这条） |
| 其它 | 报「未知命令」并打用法，退出码 1 |

退出码：成功 0，失败 1。命令行结果只有 `print`（`output.mode` 是 `text`）。

## 危险点（★ 看这里）

1. **它真改系统环境变量**：直接读写注册表 `HKCU\Environment` 的 `Path`
   （值类型 `REG_EXPAND_SZ`），写完广播 `WM_SETTINGCHANGE`。**已经开着的**终端不会变，
   新开的才看得到。
2. **只动当前用户（HKCU），不动系统级（HKLM）的 PATH**，所以不需要管理员权限。
3. **「恢复」是整体覆盖**：拿那份备份的整串写回去，覆盖前不会再自动备份一次
   （所以界面把"会加什么/会去掉什么"摆在确认之前）。恢复**会立刻写注册表**，也会把界面上
   那份没保存的草稿一起换成恢复后的样子（草稿只在点「保存」时才写，恢复不算草稿）。
4. **写回时整串重拼**：按 `;` 重新 join，读的时候空段已经丢掉，所以多余的 `;` 会被规整掉；
   PATH 里的变量（如 `%USERPROFILE%\bin`）按原样写回，**不展开**。
5. **不要让 AI 自动调用**：`pkg.json` 里 `ai.expose` 是 `false`、`risk` 是 `high` ——
   改 PATH 会立刻影响整台机器的命令解析。

## 数据放哪（`V-200`）

宿主给的 `MOSS_PLUGIN_DATA_DIR`（= `user_data/state/path/`）下面：

| 位置 | 是什么 |
|---|---|
| `data/backups/path_backup_<时间戳>.txt` | **备份**（一行一个路径，纯文本，记事本能看能改） |

放 `user_data/` 里，**重装/升级这个包不会冲掉**。界面上右下角会把实际路径显示出来。

## 直接运行 / 打包成 exe

**交给 moss 跑是最省事的**（`moss :path`）—— 自带运行时里 pywebview / WebView2 都是齐的。

自己单独跑也行（只改了 `V-207` 起的两处「按 frozen 算路径」）：

```bash
# 直接跑（用 moss 自带运行时那份 python，pywebview 是齐的）
system\runtimes\python\3.12\python.exe system\pkgs\path\main.py
system\runtimes\python\3.12\python.exe system\pkgs\path\main.py help

# 打包成 exe（在 main.py 所在目录跑；ui/ 必须跟着一起发）
python -m nuitka --onefile --assume-yes-for-downloads --windows-console-mode=force \
    --include-data-dir=ui=ui -o path.exe main.py
#   ★ 这样打出来的 exe：命令行（help / add / remove）能用；**不带参数开界面会报错** ——
#     因为没把 pywebview 打进去。要界面也能开，再加 --include-package=webview
#     （还需要目标机器有 WebView2 运行时）。
```

打包之后这些是**按 exe 的位置**算的（`sys.frozen`）：数据目录（含备份）落
`<exe 旁边>\user_data\state\path\`；界面文件从"exe 旁边 → 解包目录"两处找，都没有就给
一句人话（不开空窗）。「注册自身目录」注册的也是 **exe 所在目录**（这才是它该有的语义）。
