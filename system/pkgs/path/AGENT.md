# path —— 查看/管理 Windows 用户 PATH（带备份/恢复）

```bash
moss :path                      # 不带参数 = 打开界面
moss :path list                 # 用户级 + 系统级两级 PATH 都打出来（系统级只读）
moss :path add D:\tools\bin     # 加进【当前用户】的 PATH
moss :path add                  # 省略路径 = 这个包自己的目录
moss :path remove D:\old\bin    # 从【当前用户】的 PATH 移除
moss :path help                 # 打用法
moss :path D:\tools\bin         # 拖一个文件夹进来（或这么敲）= add 那条目录
```

## 这包干什么

**界面**：一份网页（`ui/index.html`，Vue 3），两种跑法（`V-48` / `V-200`）——
内嵌进 moss 的「界面」选项卡（`pkg.json` 的 `ui.embed`），或者 `moss :path` 自己开窗口。
`V-391` 起界面**整个重做**（上一版"主卡 + 侧栏 + 卡片"被判定像学生作业）：现在是
**一张表装两级 PATH** + 顶栏一条线 + 底栏一条线，没有任何卡片、大圆角、渐变和毛玻璃，
层级只靠**线 + 字重 + 留白**。行高 30px、分组头 34px 吸顶 —— 一屏能看全两级。
**★ 不带任何 CDN**（设计稿引的 Tailwind / lucide / SortableJS / Google Fonts 一个都没用）：
工具类按同一套数值手写成 `ui/style.css`，图标本地化在 `ui/icons.js`，拖动排序用浏览器自带的
HTML5 拖放 —— 这个包**离线可用**（探针里钉着"一个外网资源都没加载"）。

- **按注册表里的原顺序**列出当前用户 PATH（上下位次就是 PATH 的优先级 —— 顺序决定同名命令
  谁赢，所以界面不排序）；**目录已经不存在的**那几条：行首一道 2px 红竖线 +「不存在」小标
  （带 `%VAR%` 但变量没定义的**不判**，免得误伤）
- **按住行左边的把手拖动 = 调优先级**（`V-213` 新加的：拖动只改草稿，点「保存修改」才写回）
- 每行悬停出三颗小按钮（**图标 + 文字**，和别处一致）：**复制** / **拿出来改**（填回上面的
  输入框、从列表里拿掉，改完点「添加」放回去）/ **删除**
- 顶上一颗「**添加**」，干两件事：输入框**留空**点它 = 弹文件夹选择框；输入框**填了路径**
  点它 = 先问后端"这是不是个目录"（是文件就加它所在的目录，不存在就报错、输入框一个字不动）。
  输入框里一边打字一边给提示（不像路径 / 盘上没有）
- **先改后存**（`V-211`）：加 / 删 / 去重 / 清失效 / 拖动**都只改界面上的草稿** —— 新加进来的
  那几条挂着「未保存」小标（行首一道琥珀竖线）；**「撤销 / 保存修改」出现在这一级的
  分组头上**（不是右上角），旁边还写着「N 处未保存」。点保存才**一次**写回注册表、广播一次。
  有草稿时点顶栏那颗「刷新」会先问一声
- **操作按钮有事才出现**（`V-213` / `V-391`）：有重复才给「去重」、有失效才给「清理失效」、
  改了才给「撤销 / 保存修改」—— 没事的时候它们都不在页面上
- **反馈分两档**（`V-391`）：`成功`（真写进注册表，绿勾）和 `中性`（只是改了草稿，不带勾）。
  原来"加进草稿"也顶个绿勾，一屏闪三次等于没说。提示在**右下角**（居中会盖住最后几行，
  而那常常正是刚改的那几行），最多两条、同类互相顶掉，结果出来时过程提示自动消失
- 底栏一条线：左边一个状态点 +「和注册表一致 / 有没保存的改动」+ 拖动提示，右边后端自证
  （Python 版本 + 数据目录）
- **拖文件夹进窗口 = 加它**（拖**文件**则取它所在的目录，同样只进草稿）；拖动中会铺一层提示
  （拖进 moss 的「界面」选项卡那一帧里也算 —— 见契约里 `drop` 事件那一行）
- **布局：一张表装两级**（`V-391`，替掉了 `V-215` 那套"左列表 + 右 360px 侧栏"）：
  用户级、系统级各一个**分组头**（名字 / 注册表位置 / 条数 / 自己那套「未保存 · 撤销 · 保存」），
  下面是同一套列（把手 / 序号 / 路径 / 状态 / 操作）。分组头**吸顶**，滚到哪都知道自己在哪一级。
  ★ 为什么替掉：侧栏在没有备份时就是一整片空白，**占全页 30% 宽度放最没用的东西**。
- **备份收进抽屉**（`V-391`）：顶栏那颗「备份 N」按需拉出来，`Esc` / 点遮罩 / 右上 X 关掉。
  抽屉里：备份当前（可起名，留空 = 时间戳）、份数、相对当前清单的 `+增加 / −减少`、
  「对比」展开差异（`+ / − / =` 三色，默认只列差异，「显示全部」才把一样的列出来，
  **比的是界面上的草稿**，存没存都算、本地算的，不经过后端）、恢复、删除、双击名字改名。
- 老位置（`.path_editor/path_bak/`）的备份也列出来，标着「老位置」
- **行的三颗操作 hover 才浮出**（位置固定，不挤路径）：复制 / 拿出来改 / 删除
- **系统 PATH 也列出来，而且能改（`V-388` / `V-389`）**：用户级那张表下面接着就是**系统级**
  那一段（同一个表、同一套列），画的是机器级（`HKLM`）那一条。为什么要有它：**安装器
  （mingw / Qt / VS / JDK…）常常把目录写进机器级 PATH**，而界面原来只列用户级那份 ——
  于是"我明明装了，列表里怎么没有"成了最常问的一句话（不是没注册，是注册在另一级）。
  顶栏也直接写着「用户级 N · 系统级 M」。带 `%VAR%` 的先展开再看盘上有没有。
  - **能改**：拖动排序、双击就地改、行尾删除、底部加一条 —— 改的全是草稿。
  - **保存要过一次 UAC**：分组头那颗「保存到系统」。点下去会弹一次 UAC，
    只在这时用 `ShellExecuteExW(runas)` 起一个短命的 `syswrite.py` 写那**一个**值，
    写完就退；主进程始终是普通权限。UAC 上点「取消」= 这次不改，不是失败。
  - **它和用户级各有一套草稿和按钮**：上面那颗「保存修改」只写 HKCU，绝不动机器级。
  - 改动前后各备份一份到 `data/backups_system/`（**和用户级备份分开存**：右栏那颗「恢复」
    是往 HKCU 写的，混在一起会误伤）。值类型保持 `REG_EXPAND_SZ`。
  - 影响这台机器上**所有用户**，所以分组头挂着「需管理员」，字色比用户级轻一档。

**命令行**：`add` / `remove` / `list` / `help`（别名见 `pkg.json` 的 `params.desc`）。
省略 `[路径]` 时操作的是**这个包自己的目录**。

## 参数

只有一个 `rest: true` 的参数 `args`：宿主把包名后面那一整串**原样**交给包，
由包自己解析（宿主不拆词、不做引号转义）。带空格的路径请自己加引号：

| 参数 | 含义 |
|---|---|
| 留空 | 打开界面 |
| `add [路径]` | 加进 PATH；省略 = 这个包自己的目录。别名 `register` / `reg` |
| `remove [路径]` | 从 PATH 移除；省略 = 这个包自己的目录。别名 `unregister` / `del` |
| `list` | 用户级 + 系统级两级 PATH 原样打出来（**只读**，标出盘上不存在的）。别名 `ls` / `show` |
| `help` | 打用法。别名 `?` / `-h` / `--help` |
| 一个**存在的目录** | 当成 `add 那个目录`（拖文件夹进来走的就是这条） |
| 其它 | 报「未知命令」并打用法，退出码 1 |

退出码：成功 0，失败 1。命令行结果只有 `print`（`output.mode` 是 `text`）。

## 危险点（★ 看这里）

1. **它真改系统环境变量**：直接读写注册表 `HKCU\Environment` 的 `Path`
   （值类型 `REG_EXPAND_SZ`），写完广播 `WM_SETTINGCHANGE`。**已经开着的**终端不会变，
   新开的才看得到。
2. **默认只动当前用户（HKCU）**，那条不需要管理员。**系统级（HKLM）只在用户点
   「保存到系统」时才写**，而且是由 UAC 提权后的 `syswrite.py` 去写 —— 主进程本身没有
   管理员权限，也不该有（把整个界面进程提权，等于让 WebView 也拿到管理员）。
3. **「恢复」是整体覆盖**：拿那份备份的整串写回去，覆盖前不会再自动备份一次
   （所以界面把"会加什么/会去掉什么"摆在确认之前）。恢复**会立刻写注册表**，也会把界面上
   那份没保存的草稿一起换成恢复后的样子（草稿只在点「保存」时才写，恢复不算草稿）。
4. **写回时整串重拼**：按 `;` 重新 join，读的时候空段已经丢掉，所以多余的 `;` 会被规整掉；
   PATH 里的变量（如 `%USERPROFILE%\bin`）按原样写回，**不展开**。
5. **不要让 AI 自动调用**：`pkg.json` 里 `ai.expose` 是 `false`、`risk` 是 `high` ——
   改 PATH 会立刻影响整台机器的命令解析。

## 数据放哪（`V-200`）

宿主给的 `MOSS_PLUGIN_DATA_DIR`（= `user_data/state/path/`）下面：

| 位置 | 是什么 |
|---|---|
| `data/backups/path_backup_<时间戳>.txt` | **备份**（一行一个路径，纯文本，记事本能看能改） |
| `.path_editor/path_bak/` | **老位置**：仍然认（能列、能恢复、能删），但**不再往里写** |

放 `user_data/` 里，**重装/升级这个包不会冲掉**。界面上右下角会把实际路径显示出来。

## 直接运行 / 打包成 exe

**交给 moss 跑是最省事的**（`moss :path`）—— 自带运行时里 pywebview / WebView2 都是齐的。

自己单独跑也行（只改了 `V-207` 起的两处「按 frozen 算路径」）：

```bash
# 直接跑（用 moss 自带运行时那份 python，pywebview 是齐的）
system\runtimes\python\3.12\python.exe system\pkgs\path\main.py
system\runtimes\python\3.12\python.exe system\pkgs\path\main.py help

# 打包成 exe（在 main.py 所在目录跑；ui/ 必须跟着一起发）
python -m nuitka --onefile --assume-yes-for-downloads --windows-console-mode=force \
    --include-data-dir=ui=ui -o path.exe main.py
#   ★ 这样打出来的 exe：命令行（help / add / remove）能用；**不带参数开界面会报错** ——
#     因为没把 pywebview 打进去。要界面也能开，再加 --include-package=webview
#     （还需要目标机器有 WebView2 运行时）。
```

打包之后这些是**按 exe 的位置**算的（`sys.frozen`）：数据目录（含备份）落
`<exe 旁边>\user_data\state\path\`；界面文件从"exe 旁边 → 解包目录"两处找，都没有就给
一句人话（不开空窗）。「注册自身目录」注册的也是 **exe 所在目录**（这才是它该有的语义）。

## 来历

原样搬自旧项目 `QuickTools\pa_soft\bin\cli\path\`（旧宿主里的 `pa :path`），注册表读写、
备份格式、命令行语法都是**机械移植**。后来改过这几处：

1. 界面从 **tkinter**（`PathEditorApp` / `RestoreWindow`，还依赖 `windnd` 收拖放）
   换成**网页**（`ui/`，Vue 3 + `moss-embed.js` 垫片）—— 契约里写着"界面写成网页、
   别用 Tk 写新包"（`V-58`），而且现在一份界面内嵌/独立窗口通用，`windnd` 也不再需要
   （拖文件夹进来的事由 moss 那边负责）。
2. 备份从 `.path_editor/path_bak/` 挪到 `data/backups/`（契约的 `data/` 目录）；
   老位置只读认。
3. `add` / `remove` 省略路径时用**这个包自己的目录** —— 老代码用的是**数据目录**，
   等于把 `user_data/state/path` 加进 PATH，没道理。
4. 第一个位置参数不是命令、但**是个存在的目录**时，当成 `add`（拖文件夹进来那条路）。
5. 界面上改 PATH 从"点一下就写"换成**先改后存**（`V-211`）：草稿在网页里（`ui/app.js`），
   只有「保存」调后端的 `save`，后端 `save` 是**原样写**（只去空串 + `normpath`，不替用户
   去重、不排序）。包的那个网页长什么样、点下去对不对，靠 `tools/path界面探针.py` 真跑一遍
   （假后端 + 真点击）；后端那条靠 `probe_path` / `save` 的探针。
6. 界面**整个重做**（`V-391`）：从"主卡 + 侧栏 + 卡片"改成**一张表装两级 PATH**，
   备份收进抽屉，行高压到 30px。原来那份探针量的全是旧设计的尺寸（`.card` 的圆角、
   `.aside` 的 360px、失效行的红色斜纹……），界面一换它就红一屏 —— 所以探针**跟着重写**，
   现在量的是新设计的规矩（见下）。
