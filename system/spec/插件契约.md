# moss 插件契约（spec 1）

> **写一个能跑的插件，只需要读完这一页。**
>
> 这份文件随 `moss.exe` 一起分发，与当前版本一致。内核内部怎么实现
> （数据目录怎么命名、记忆怎么存、升级怎么迁移……）**不用管** —— 那是宿主的事。
>
> 给 AI 的读法：先看 §1，再看 §2 的完整例子，然后照 §3 的字段表填。
> 命令：`moss --spec` 随时打印本文；`moss --new <id>` 直接生成一个能跑的骨架。

---

## 1. 一分钟版本

0. **★ 要界面？先看这条（默认就走它）**：**界面写成网页（HTML），在 `pkg.json` 里声明
   `"ui": {"embed": "ui/index.html"}`** —— 于是同一份界面**既能内嵌进 moss 的「界面」选项卡、
   又能自己开窗口**（`moss :<id>`）。照 `system/pkgs/bmi/` 抄，规范见 §4.2。
   **别一上来就 `webview.create_window` 自己开窗口**（那是例外，不是默认）；也**别用 Tk** 写新包。
   什么时候才不这么做：① 必须是个独立的大窗口（比如要铺一片缩略图）；② 界面必须用非网页技术
   （Tk / 原生控件）；③ 这个包根本没有界面（命令行 / 托盘 / 后台）。这三种情况下也**照旧要给
   `AGENT.md` 写清为什么**。

1. **一个插件 = 一个目录**，至少两个文件：`pkg.json`（声明，零代码）+ 代码文件（真代码）
2. **放哪**：自己用 → `user_data/pkgs/<id>/`　要随 moss 发出去 → `system/pkgs/<id>/`
3. **`id`**：小写字母开头，只允许 `a-z 0-9 _ -`，≤32 字符，**发布后不能改**
4. **要存东西**：读 `MOSS_PLUGIN_DATA_DIR`，在里面用 `data/`（持久，要备份）、
   `cache/`（可再生）、`tmp/`（随便清）、`logs/`（日志）。
   **绝不往自己包目录里写数据**（重装/升级会把包目录整体换掉）
5. **要密钥**：**绝不写进 `pkg.json`**（分享插件就等于泄露），用 `keyRef` 指向宿主
   secrets —— 这一块宿主**还没实现**，见 §7
6. **要结构化结果**：把 JSON 写进 `MOSS_RESULT_FILE`；给人看的东西照常 `print`
7. **参数**：在 `params` 里声明，宿主把值以 JSON 放进 `MOSS_PKG_PARAMS`
8. **要能被拖进来**：写 `drop`（**不写＝完全不收拖入**）。收文件 / 收文件夹分开声明 ——
   **能用文件夹解决的就别写 `file`**（`tree` / `mark` / `sync` 只收文件夹）；
   **只认某几种格式就把 `ext` 写上**（不写＝什么都收，写了就得跟代码的事实一致）。见 §3

## 2. 最小完整例子

```
user_data/pkgs/my-first/
├─ pkg.json
└─ run.py
```

`pkg.json`：

```json
{
  "spec": 1,
  "id": "my-first",
  "kind": "task",
  "version": "0.1.0",
  "name": { "zh-CN": "我的第一个插件" },
  "desc": { "zh-CN": "把输入重复几遍" },
  "aliases": ["myfirst"],
  "runner": "python",
  "entry": { "file": "run.py" },
  "params": [
    { "name": "text", "type": "string", "default": "你好", "desc": "要重复的内容" },
    { "name": "times", "type": "int", "default": 1, "desc": "重复几遍" }
  ],
  "output": { "mode": "json", "schema": { "text": "string", "times": "int" } }
}
```

`run.py`：

```python
import json, os

params = json.loads(os.environ.get("MOSS_PKG_PARAMS") or "{}")
text = str(params.get("text") or "你好")
times = max(1, min(int(params.get("times") or 1), 100))

for _ in range(times):
    print(text)                       # 给人看

data_dir = os.environ["MOSS_PLUGIN_DATA_DIR"]
os.makedirs(data_dir, exist_ok=True)  # 宿主只给路径，目录由你自己建

result = {"text": text, "times": times}
with open(os.environ["MOSS_RESULT_FILE"], "w", encoding="utf-8") as f:
    json.dump(result, f, ensure_ascii=False)   # 给机器看
```

跑：`moss :my-first 你好 3`（或 `moss :myfirst text=你好 times=3`）

## 3. `pkg.json` 字段表

`内核` 那一列是**诚实标注**：✅ 真在用；⚠️ 声明保留、宿主会读但不据此做事；❌ 只是占位，将来才实现。

| 字段 | 必需 | 说明 | 内核 |
|---|---|---|---|
| `spec` | 建议 | 格式版本，现在固定 `1` | ✅ |
| `id` | ✅ | 机器身份：目录名 / 台账键 / 数据目录名。**发布后不能改** | ✅ |
| `kind` | ✅ | `task` 跑完就结束 · `app` 界面型（会藏控制台窗口） · `agent` 预留 | ✅ |
| `version` | ✅ | 包自己的版本，你自己维护（跟 moss 版本无关） | ✅ |
| `name` `desc` | ✅ | 展示名与说明，**多语言对象** `{"zh-CN": "…", "en": "…"}` | ✅ |
| `aliases` | ⬜ | 你敲的短名，可多个（`moss :myfirst`） | ✅ |
| `icon` | ⬜ | 图标文件名（相对包目录）。**不写就在包里自动找 `icon.svg` → `icon.png` → `icon.webp` → `icon.jpg` / `icon.jpeg` → `icon.ico` → `icon.gif` → `icon.bmp`**，命中第一个就用；都没有也算合法（命令行包常常不需要图标）。宿主会把绝对路径注入 `MOSS_PKG_ICON` 给包 | ✅ |
| `tags` | ⬜ | 检索用 | ✅ |
| `runner` | ✅ | `python` / `go` / `html` / `exe` / `shell` / `powershell` | ✅ |
| `entry.file` | ✅ | 入口代码文件（相对包目录）。纯 `inline` 形式可省 | ✅ |
| `params` | ⬜ | 参数声明，见下 | ✅ |
| `env.cwd` | ⬜ | 用哪个目录当工作目录；不写＝你敲命令时所在的目录 | ✅ |
| `env.elevated` | ⬜ | 预留：要不要管理员权限 | ❌ |
| `output` | ⬜ | 结果形状（`mode` + `schema`），给人/AI 看 | ⚠️ |
| `capabilities` | ⬜ | 能力声明（`net` / `clipboard` / `fsRead` / `elevated`） | ❌ |
| `verify` | ⬜ | 自检（自我迭代闭环用） | ❌ |
| ~~`origin`~~ | — | **别在包里写来源**（2026-09-27 `F-10` ❌）：来历写进 `AGENT.md` 的「来历」一节；而「这包是官方的还是第三方装的」属于**宿主记账**（包自证不可信）—— 形态等商店那轮定 |
| `ai` | ⬜ | `expose` / `risk` / `examples`（AI 工具面） | ❌ |
| `docs` | ⬜ | `readme` / `agent` 指向文件 | ❌ |
| `drop` | ⬜ | **拖进来收不收、怎么收**（含"只收哪几种扩展名"）—— 见下 | ✅ |
| `accepts` | ⬜ | 更宽的"能接受什么输入"（打开方式 / AI 选取那类用途）—— 拖放这块**已经由 `drop` 承担**，这里只留个坑位（`F-25` ⬜ 还没定） | ❌ |

**未知字段会被原样保留**（`F-21`）—— 老宿主读到新包不会把它写残。

`params` 每一项：

| 键 | 说明 |
|---|---|
| `name` | 参数名（`key=value` 写法时用的就是它） |
| `type` | `string`（默认） / `int` / `float` / `bool` |
| `required` | 必填？缺了宿主会报错 |
| `default` | 默认值 |
| `placeholder` | 界面输入框的提示文字 |
| `desc` | 说明 |
| `rest` | ★ 设成 `true` 表示"**剩下的参数全归我，我自己解释**"（宿主不做 argv 数组、不做引号转义，整串交给你） |

`drop` —— **拖文件/文件夹进 moss 窗口**（`V-38` / `V-183`）。**不写＝完全不收拖入**。对象或数组都行（数组＝多条拖入命令）：

```json
"drop": {
  "dir":  { "cwd": true },
  "file": { "cwd": true, "param": true, "base": true, "ext": ["png", "jpg"] }
}
```

| 键 | 说明 |
|---|---|
| `label` | 投放框上的字，默认「运行」 |
| `file` / `dir` | 收文件 / 收文件夹（`false`＝不收这一种）。**用不上就别写** |
| `cwd` | 把它当工作目录；拖的是文件＝**文件所在的目录** |
| `param` | 路径追加到参数串末尾 |
| `quote` | 加双引号，默认 `true`（不加引号的 `C:\a\b.ico` 过 `shlex` 会变成 `C:ab.ico`） |
| `base` | 只给文件名（配合 `cwd`） |
| `ext` | **只收这几种扩展名**（只在 `file` 里）：小写不带点；**不写＝什么都收**；`[]`／`"*"` 也＝什么都收；文件夹不看它 |

**两条硬要求**：① **能收文件夹就够的，别写 `file`** —— `tree` / `mark` / `sync` 只收文件夹。声明窄一点，拖动时列表才干净，不该收的东西根本不会来烦你；② **声明必须跟代码一致** —— `img` 的 `ext` 就是它 `core.py` 里的 `SUPPORTED_EXTS`，多写一个就是把处理不了的文件塞进来白跑。

拖动那一刻 moss 按声明筛列表（拖 `.txt` 时只收图片的包不出现）；松手后拿**真实路径**再判一次，不匹配就说清原因、不跑。

## 4. 宿主注入的环境变量

| 变量 | 是什么 |
|---|---|
| `MOSS_HOME` | 安装根（`moss.exe` 所在目录） |
| `MOSS_USER_DATA_DIR` | `user_data/` 的完整路径 |
| **`MOSS_PLUGIN_DATA_DIR`** | **你的数据根**（`user_data/state/<你的 id>/`） |
| `MOSS_PLUGIN_CACHE_DIR` / `MOSS_PLUGIN_LOG_DIR` / `MOSS_PLUGIN_TMP_DIR` | 三个约定子目录的完整路径。**宿主只给路径、不预建**，你用哪个就自己 `makedirs` |
| `MOSS_PKG_ID` / `MOSS_PKG_VERSION` | 你是谁 |
| `MOSS_PKG_PARAMS` | 参数（JSON 字符串） |
| `MOSS_ARGS` | 原始参数字符串（空格连接） |
| `MOSS_VIA` | 谁触发的：`cli` / `history` / … |
| `MOSS_RESULT_FILE` | ★ 把结构化结果写进这个文件 |
| `MOSS_VENV` | 宿主识别到虚拟环境时给出 |
| `MOSS_APPEARANCE` | 外观 JSON（深浅色 / 强调色），界面型包用 |
| `MOSS_PKG_ICON` | **你自己图标的绝对路径**（来自 `icon` 字段或自动发现的 `icon.*`）。没有图标时**不注入**（别去猜文件名） |
| `PYTHONIOENCODING` | 宿主设成 `utf-8`（你自己设过就尊重你的） |
| `MOSS_INTERACTIVE` | ★ 设成 `1` 表示**有人在听你说话**：你现在 `input()` 能拿到回答（界面那边命令行下面有一行输入）。**没设**就表示"没人在听"（比如从计划任务、或没有人看着的后台跑起来）—— 这时候**别去 `input()`**，那会永远卡住；给个明确的用法提示（像 `:img` 那样列出 `-o <目录>` / `/` 两种非交互写法） |

### 4.1 想"问用户一句话"怎么写

**别只看 `sys.stdin.isatty()`** —— 界面模式下 stdin 是一根管子，`isatty()` 永远是假，
可界面其实**能**回答你。正确的判据是"真终端 **或者** 宿主说有人在听"：

```python
import os, sys

def can_ask():
    if sys.stdin.isatty():
        return True
    return str(os.environ.get("MOSS_INTERACTIVE") or "").strip() not in ("", "0", "false")

def ask(prompt, choices):
    if not can_ask():
        print("这里没法交互，请明确指定：…（列出非交互的写法）")
        return None
    print(prompt)
    for i, c in enumerate(choices, 1):
        print("   %d) %s" % (i, c))
    try:
        return int(input().strip())
    except (EOFError, ValueError):
        return None
```

**一条铁律：只认环境变量，不要猜路径。** 宿主的内部布局随时可能变
（`state/` 的目录名就改过一次），而环境变量是对外承诺。

## 4.2 界面：一份代码，两种跑法（`V-47` / `V-48` ✅）

**想要界面，就把界面写成网页。** 同一份 HTML 既能被嵌进 moss 的「界面」选项卡，也能
自己开一个窗口 —— 靠这个块的**第三个**脚本（垫片）自动分流，界面代码一个字都不用改。

### 声明（`pkg.json`）

```json
"ui": { "embed": "ui/index.html", "title": { "zh-CN": "BMI 计算器" } }
```

路径**相对包目录**。**不写就没有「界面」选项卡**（那个选项卡只在当前包声明了它时才出现）。

### 页面里怎么跟后端说话

页面里引三个东西（顺序别换）：

```html
<script src="vendor/vue.global.prod.js"></script>   <!-- 你的框架，**本地**放着 -->
<script src="moss-embed.js"></script>                <!-- 垫片：从示例包抄走即可 -->
<script src="app.js"></script>
```

然后**只认这一套**（`window.moss`）：

```js
await moss.call('bmi', {height: 175, weight: 70});   // 调后端的方法（后端就是你的 main.py）
moss.on('time', d => { ... });                       // 接后端**主动推**的事件
moss.on('ready' | 'invoke' | 'drop' | 'theme' | 'visible' | 'close', fn);
moss.env.embedded;                                   // true = 被嵌在 moss 里；false = 独立窗口
```

老写法（`window.pywebview.api.xxx()`）**也能用** —— 垫片在内嵌环境下把它垫出来了，
所以 `img` / `exec` 那种现成界面搬进来不用改代码。

### 后端怎么配合

| | 独立窗口（`moss :bmi`） | 内嵌（界面里点「运行」） |
|---|---|---|
| 你怎么知道 | 环境里**没有** `MOSS_UI_EMBED` | 宿主机给了 **`MOSS_UI_EMBED=1`** |
| 你该干什么 | 自己 `webview.create_window(url=…, js_api=Api())` | **别开窗口**，在 stdin/stdout 上说话 |
| 调用怎么回 | `js_api` 的方法（收到的是一份 dict） | 一行一个 JSON 对象 |

内嵌模式的协议（**一行一个 JSON 对象**，`{` 开头的才算消息）：

```jsonc
// 界面 → 你（一行一条，写在 stdin 上）
{"id": "r1", "method": "bmi", "params": {"height": 175, "weight": 70}}
// 你 → 界面（成功 / 失败）
{"id": "r1", "ok": true,  "result": {"bmi": 22.86, "level": "正常"}}
{"id": "r1", "ok": false, "error": "身高体重都得是数字"}
// 你 → 界面（主动推，没有 id）
{"event": "time", "data": {"text": "18:29:42"}}
```

★ 宿主自己的横幅是 `[执行] / [目录] / [PID]` 这种**数组样子**的行，它不会被当消息 ——
你自己 `print()` 的东西也一样，会进「命令行」那一页。所以**别怕打印**。

### 几条要记住的

* **切走不会关**：切到别的选项卡、甚至去开别的包的界面，你那一页和后端进程都照旧跑着。
* **一个包一帧**：同时跑几个包的内嵌界面是可以的；界面那边只显示当前这个。
* **拖进来的文件/文件夹也会送到这一帧**：拖放那一刻，宿主把**真实路径**当 `drop` 事件发进来（`moss.on('drop', d => d.items)`）—— 前提是这个包**收得下它**（看 `drop` 声明）。所以界面型包想"拖文件夹进来加一条"，不用自己解析参数。
* **可以被弹成独立窗口**：用户能把这一帧"弹出"到 moss 的另一扇窗（点最小化＝收回主窗口，点关闭＝结束）。弹出/收回时那一帧会**重新加载**（新文档）—— **后端进程不动**，所以状态放后端就丢不了；只在页面里（输入框、选择）的会重来。
* **别在页面里干重活**：能放后端的都放后端（这一版的示例里，BMI 和时间都在 Python 那边）。
* **页面是怎么送到你面前的**：内嵌时宿主会起一个**只绑 `127.0.0.1` 的临时本地服务**
  （随机端口 + 本次会话的随机 token 在路径里），你的 `index.html` 和它的 css/js 都从那儿取。
  ⇒ `fetch` / `localStorage` 都能正常用（`file://` 下是不行的；而且**WebView2 里压根不能
  iframe 一个 `file://` 页面** —— 帧是空的、连 `load` 都不触发，所以宿主才走了这条路）。
  但那是**本机地址**：要联网（调 API 之类）还是走你的后端去发。
* 界面文件**别引用网络上的东西**（CDN 之类）：离线就跑不起来了。要用的库跟示例包一样
  放进 `ui/vendor/`。

**照着抄**：`system/pkgs/bmi/` 就是最小样板 —— `main.py`（两种模式）、
`ui/index.html` + `ui/app.js`（Vue 3）、`ui/moss-embed.js`（垫片，直接抄走）。

### 写界面型包最容易踩的三个坑（都实测过）

1. **JS 桥的方法要收得下那一个参数**：pywebview 把 JS 那边的实参原样传进来 ——
   界面里 `moss.call('now', {})` 就会调成 `Api.now({})`。写 `def now(self):` 就是
   `TypeError: now() takes 1 positional argument but 2 were given`。
   一律写 `def now(self, params=None):`。
2. **别把 `window`（或任何带循环引用的对象）挂成 `js_api` 实例的属性** ——
   pywebview 生成桥时要遍历这个对象的属性，挂上去**整个桥会失效**：实测
   `window.pywebview.api` 的方法列表变成空的、页面里每个调用都失败，控制台还会刷一屏
   `Empty.Empty.Empty…: maximum recursion depth exceeded`。要拿窗口就用闭包 / 模块变量。
3. **想证明"是 Python 在干活"就 `print`**：内嵌模式下，你 `print` 的东西会进 moss 的
   「命令行」那一页（宿主横幅也在一起）；独立窗口模式下进控制台。示例包里每个方法都
   打了一行（`[bmi] Python 算完：175 cm / 70 kg → BMI 22.86（正常）`）。

## 5. 数据放哪


| 你的东西 | 放哪 | 能删吗 | 重装/升级这个包 |
|---|---|---|---|
| 持久数据（会话、索引、用户上次的设置） | `MOSS_PLUGIN_DATA_DIR/data/` | ❌ 不能 | 不碰 |
| 可再生缓存 | `cache/` | ✅ 随时 | 不碰 |
| 临时落盘 | `tmp/` | ✅ 随时 | 不碰 |
| 日志 | `logs/` | ✅ 可清 | 不碰 |
| **要交给用户用的产出**（生成的文档 / 代码 / 图片） | **让用户选目录**（把选择记进 `data/`），别藏在 `data/` 里 | —— | —— |

最后一条是经验：`data/` 在 `user_data/state/` 深处，用户根本找不到。
`img` 就是这么做的 —— 界面上让用户选输出目录，只把自己的偏好记在 `data/`。

## 6. 结果与输出

- **`print` 是给人看的**：随便打，宿主直接透传到控制台
- **结构化结果是给机器/AI 看的**：写进 `MOSS_RESULT_FILE`（JSON）。
  宿主读回后打一行 `[结果] {...}`，同时也是远程调用 / AI 工具的返回值
- 建议在 `output.schema` 里声明形状（现在只是声明，但界面与 AI 工具面以后靠它）

## 7. 密钥（★ 宿主尚未实现）

要接 API key 的插件，**唯一正确姿势**是在 `pkg.json` 里引用、而不是携带：

```json
{ "env": { "apiKey": "keyRef:openai_key" } }
```

宿主负责：从 `user_data/secrets/` 取值（DPAPI 加密，当前用户作用域）、
注入给子进程、并且**在日志与界面里脱敏**。

⚠️ **这一块还没实现**（`D-07` 仍是设计）。在那之前：

- **不要把 key 写进 `pkg.json` 或包目录** —— 插件是要分享给别人的
- 临时办法：让用户自己设环境变量，你在代码里读（如 `os.environ.get("OPENAI_KEY")`）

## 8. 三条最容易踩的坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 把 API key 写进 `pkg.json` | 分享插件＝泄露 key | 用 `keyRef`（§7）；没实现前用环境变量 |
| `id` 用大写 / 中文 / 空格 / 点 | 包**被跳过**（控制台有警告），用户只看到"包不见了" | `^[a-z][a-z0-9_-]{0,31}$` |
| 数据写在自己包目录里 | 重装/升级包时**数据被冲掉** | 写 `MOSS_PLUGIN_DATA_DIR` |

## 9. runner 与语言

| runner | 跑什么 | 备注 |
|---|---|---|
| `python` | `.py` | 自带 Python 运行时；**不要假定装了第三方库** |
| `go` | `.go` | 需要 Go 工具链，慢（每次编译） |
| `exe` | 编译好的可执行文件 | ★ **出厂包应该用这个**（见下） |
| `html` | 网页，用默认浏览器打开 | 包不一定是脚本 |
| `shell` / `powershell` | `.bat` / `.cmd` / `.ps1` | |

**编译型语言（Go / Rust / C）出厂时要带编译好的 `exe`，不要带源码**：
源码要用户装整套工具链（Go 约 500MB），而且每次运行都要重新编译
（实测 `go run` 约 19 秒，编译好的 exe 约 0.05 秒）。源码留在 `src/`，
用 `build.cmd` 产出 exe，`entry` 指向 exe。

## 10. 版本与兼容

- `spec` 现在是 `1`。规则：**只许加字段，不许改语义**（`V-09`）
- 你的 `pkg.json` 里不认识的字段，老版本 moss 会**原样保留**
- 你的包的 `version` 你自己管；升级包用 `.qtp`（尚未实现）

## 附：AI 用「版本快照」的推荐流程（`V-108`）

给 AI（或脚本）用的一套备份/恢复通道。**动手改东西之前先钉一个点，改坏了能一键回到那个点。**

### 命令
```bash
moss --snap save :<包名> --title "动手前" --tag before-ai   # ① 钉点（--tag 便于回）
moss --snap ls   :<包名>                                    # 这次快照里有什么
moss --snap cat  :<包名> <路径>                             # 看某个文件**当时**的内容
moss --snap grep :<包名> <关键词> [目录]                     # 在快照里搜内容（只读）
moss --snap diff :<包名>                                    # 和现在比：变了/缺了/多了/空的
moss --snap revert :<包名> before-ai                        # 一键「对比 + 回退」（先看再动）
moss --snap revert :<包名> before-ai --yes                  # 真回退（只写回，多出来的不动）
moss --snap revert :<包名> before-ai --yes --sync           # 连多出来的也挪进回收站（一模一样）
moss --snap tags :<包名>                                    # 钉过哪些点
moss --snap check :<包名>                                   # 按指纹校验（被改过看得见）
moss --snap ignore                                          # 看过滤规则（哪些不会被存）
```

### 三条硬规矩
1. **会动磁盘的动作必须显式 `--yes`**（`revert` / `restore` / `export` / `rm` / `gc`）—— 不给就只打印"会干什么"，不动手。
2. **退出码分档**：`0` 成功 / `2` 用法错（含缺 `--yes`）/ `3` 没东西可做 / `4` 出错。**别去猜中文输出**。
3. **恢复的语义就是 git 的语义**：默认 = `git restore`（只写回：缺的补上、不一样的回退、覆盖前留 `.bak`，**多出来的不动**）；
   加 `--sync` = `git reset --hard`（多出来的挪进 `user_data/trash`，**不真删**）。

### 只读优先
`cat` / `grep` / `ls` / `diff` / `show` **都不会写任何东西**，而且 **`cat` 只吐内容、不给你可写路径** ——
备份库里的内容是**按指纹命名**的，把那个内部路径交出去等于把只读资产变成可写目标。
真要落盘得显式 `--snap cat … --save-to <目录> --yes`。

### 过滤
存快照时会按 `user_data/snapshot.ignore` 过滤（写法同 `.gitignore` 的常用那几条：
`*.log` / `build/` / `**/deep.txt` / `!keep.log` / `#` 注释）。**先 `moss --snap ignore` 看清单**，
或用界面上创建快照那块里的「试算」按钮先看会存哪些。

### 坏了怎么查
```bash
moss --snap diff :<包名>          # 现在和上次快照差在哪（哪个文件变了/没了/多了）
moss --snap cat  :<包名> <文件>   # 那个文件原来写的是什么
moss --snap check :<包名>         # 备份库自己有没有被改坏（按指纹验）
```

### 目录（不是插件）怎么用
快照的"对象"可以是**任意目录**，不限于插件。外部目录（不在 `user_data` / `system` 里的）照样能存：

```bash
moss --snap group "D:\python\game\pygame图片处理测试"     # 先问：它落在哪个分组（只算不算存）
moss --snap save  "D:\python\game\pygame图片处理测试" --title "动手前" --tag before-ai
moss --snap ls latest
moss --snap diff latest "D:\python\game\pygame图片处理测试"
moss --snap revert before-ai --yes                        # 在那个目录里跑就直接这么说
```

分组规则（`user_data/backups/<组>/`，`--snap group` 一问就知道）：
| 对象 | 组名 |
|---|---|
| 插件（`:md5` / `md5`） | `md5` |
| 整个 `user_data` / `system` | `@user` / `@system` |
| 普通目录（纯 ASCII 名） | `@dir-<目录名>` / `@abs-<目录名>` |
| **中文名 / 带空格的目录** | `@dir-<8位哈希>` / `@abs-<8位哈希>`（名字削没了会撞车，所以补哈希） |

在**那个目录里**跑时，`latest` 和"当前目录"都能省：`moss --snap save . --tag 动手前` → `moss --snap revert 动手前 --yes`。

## 附：AI 参数怎么拿（`V-137` / `V-139`）

以前每个包自己存一份 key（`user_data/state/<包>/config.json`）—— 于是"换个模型要改好几个地方"，
而且每份都得自己解析、自己打码。现在**只有一处**：全局设置里的 AI 组。

### 存在哪

`user_data/config.toml`（**明文**，在 user_data 里，不进仓库、不进发行版）。
**一组就四样**：组名 + 下面三个键。

```toml
[ai]
active = "DeepSeek"                 # 当前用哪一组

[ai.profiles.DeepSeek]              # 组名随便起（中文也行，写进文件时自动加引号）
base_url = "https://api.deepseek.com/v1"
api_key = "sk-…"
model = ["deepseek-chat", "deepseek-reasoner"]   # 可以多个，第一个当默认
```

★ **温度 / 上限 / 流式 / 超时这类参数不在这里**（`V-139`）：它们是"每次调用"该由代码
当场定的东西，配置里只留"连哪儿、拿什么钥匙、这个服务有哪些模型"。包自己决定怎么请求。

### 包里怎么拿（推荐：不碰文件）

跑包时宿主会把**当前那一组**注入成环境变量（**只注入这一组真填了的字段**，没填的就没有）：

| 变量 | 含义 |
|---|---|
| `MOSS_AI_PROFILE` | 组名（"我现在用的是哪一组"，写日志用） |
| `MOSS_AI_BASE_URL` | OpenAI 兼容的地址，填到 `/v1` 为止 |
| `MOSS_AI_API_KEY` | 密钥（明文） |
| `MOSS_AI_MODEL` | **第一个**模型（默认那个） |
| `MOSS_AI_MODELS` | **全部**模型，逗号隔开（要按需挑用哪个就读它） |

```python
import os
base  = os.environ.get("MOSS_AI_BASE_URL") or ""
key   = os.environ.get("MOSS_AI_API_KEY") or ""
model = os.environ.get("MOSS_AI_MODEL") or ""
if not (base and model):
    print("还没配 AI —— 打开「设置 → AI」挑一家，或 moss --ai-profile-set 名字 base_url=… model=…")
    raise SystemExit(2)
models = [m for m in (os.environ.get("MOSS_AI_MODELS") or model).split(",") if m]
# 请求：POST {base}/chat/completions，body 里带 model / messages（stream 要不要由你自己定）
```

★ **别在包里再存一份 key**（那是第二处真相）；也别在包里读 `config.toml`（格式会变，环境变量才是契约）。

### 命令行（脚本 / AI 自己用）

```bash
moss --ai-config                  # 看当前那组（key 默认打码）
moss --ai-config --profile DS --reveal     # 指定组 + 明文
moss --ai-presets                 # 常见那几家的预制参数（面板「常用」那排就是它）
moss --ai-profile-set DS base_url=https://api.deepseek.com/v1 model=deepseek-chat,deepseek-reasoner
moss --ai-active DS               # 切当前组
moss --ai-rename DS DS-备份        # 整组改名（key 不用再读一遍）
moss --ai-test DS                 # 测试连接：流式发一个最小请求
moss --ai-profile-del DS          # 删一组
moss --ai-import-legacy           # 把老的 user_data/state/ai/config.json 导成一组
```

退出码：`0` 成功；`1` 参数/组不存在或没填全；`4` **没连上**（`--ai-test` 专用）。

### 界面上

「设置 → AI」是**两张脸**（`V-140`）：

- **列表**（默认）：一组一行 —— 名字 / 接口地址 / 模型 / `key 已填` 还是 `⚠ key 没填`，
  当前那组挂一颗「当前」；每行有 `设为当前 / 编辑 / 删除`，底下是「**新建一组**」。
  **一组都没配过**的时候就一句「还没有配过 AI…」+ 那颗「新建一组」（不会一上来摊开一堆输入框）。
- **编辑**（点「新建一组」或某行的「编辑」才进来）：新建时先给一排「**常用**」
  （DeepSeek / Gemini / OpenAI / Kimi / 通义千问 / 智谱 / 硅基流动 / 本地 Ollama / 自定义）
  —— 点一下就把**名字 / 接口地址 / 模型**填好，你只需要把 key 粘进去；
  四个字段：名字 / 接口地址 / 密钥（默认打码，点「露出来」才看明文）/ 模型（一行一个）。
  底下 `保存这一组` / `测试连接`（真发一个流式请求，把 HTTP 码和第一个增量显示出来）/ `返回列表`。

界面上保存的也是 `config.toml`，和命令行同一份存储；改「名字」保存 = 给这组改名（密钥不会动）。
